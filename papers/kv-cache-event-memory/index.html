KV Cache 与事件记忆专题

从跨控制步复用、事件驱动写入到流式长期检索的 11 篇论文路线

← 返回总站
专题问题：VLA 与 Video LLM 的历史不应等同于持续增长的 context。系统需要在每个时间步判断：哪些已有 KV 可直接复用（reuse），哪些局部状态必须刷新（refresh），哪些经事件确认的信息应压缩并写入长期记忆（commit），以及如何在后续 query 到来时检索并回载。

11 篇工作如何覆盖完整路径

系统环节代表工作关键问题面向 VLA 的含义
控制步复用VLA-Cache相邻观测哪些 token 没有变化？降低逐控制步 prefill 与 attention 成本。
事件写入KEMO、StreamMem、HERMES哪些变化值得保留，且如何在固定预算中压缩？将 motion、appearance、robot state 共同作为 commit 门控。
多任务运行时OxyGen控制、对话和记忆构建如何共享同一观测？跨任务共享 KV，避免重复编码。
长期检索ReKV、LiveVLM、StreamKV如何从长历史中找到 query 相关证据？以事件段、摘要和外部存储组织可回载历史。
预算与压缩InfiniPot-V、Video-MemComp、VidKV有限显存应分给哪些 token、层和精度？用事件重要性补足时间冗余、层敏感度和量化策略。

建议系统架构

L0 · 热路径

当前控制窗口

以 VLA-Cache 为参照，复用稳定 token，仅刷新局部变化区域的 KV；这条路径服务固定频率的动作控制。

L1 · 事件层

确认后写入

以 KEMO、StreamMem 和 HERMES 为参照，用 motion 提出候选，再以 appearance 与 robot state 确认，将状态转移写成事件级 KV 或摘要。

L2 · 冷历史

检索与回载

以 ReKV、LiveVLM 和 StreamKV 为参照，将事件段存入可检索历史；必要时以 InfiniPot-V、Video-MemComp、VidKV 控制容量与精度。

推荐阅读顺序

阶段阅读顺序目标
VLA 基线VLA-Cache → KEMO区分跨步计算复用与事件驱动长期记忆写入。
流式记忆StreamMem → HERMES → OxyGen理解固定预算、分层语义和多任务共享运行时。
长历史检索ReKV → LiveVLM → StreamKV比较外部回载、短长双缓存与事件分段检索。
极限压缩InfiniPot-V → Video-MemComp → VidKV比较 token 淘汰、逐层预算和低比特量化的互补关系。
