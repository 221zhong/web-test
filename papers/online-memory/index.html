专题三：在线记忆

VLA 在闭环操控中如何写入、保存、检索并在动作端使用任务内历史——13 篇论文路线

← 返回总站
专题问题：前两个专题回答「何时写入」与「以什么形式保存」，但它们大多停在感知侧的表征与预算。真正跑闭环时，记忆必须落在控制回路里：写进去的东西要在几十到几百个控制步之后改变动作，而且每一步都要付出延迟与显存。本专题的 13 篇工作全部是因果在线设定——推理时只能看当前与过去的观测，不能取未来帧，也不能读 oracle 状态；数字均来自各论文自己的模型、任务与协议，不能横向排名。

13 篇工作如何覆盖完整路径

系统环节代表工作关键问题对本专题的含义
写入触发MEM、EvoMem-VLA子任务边界与状态变化，哪个才是记忆的自然单位？写入时机决定记忆粒度：一段视频、一次交互，还是一次状态差分。
记忆表征MemoryVLA、Chameleon、NativeMEM、SimpleMemVLA记忆存 token、事件、单帧压缩 token，还是原封不动的视频？表征越接近原观测，保真越高、预算越贵，这是本专题的主轴。
长期维护VPWEM、ReMem-VLA固定预算下，如何让每步计算与显存近似常数？递归压缩与 recurrent query 是两条把历史「折进」固定状态的路。
索引与检索MemER、MemoryVLA未来需求未知时，靠什么条件把对的证据找回来？检索条件从语言目标，扩展到了控制状态与任务进度。
动作接口MemoryVLA++、Chameleon记忆如何进入 action head，是条件化还是先生成子任务？记忆不是额外输入，而是改变扩散/flow 策略条件分布的信号。
评测MIKASA-Robo、RoboMME、RMBench怎么证明「记不住就做不对」？三个基准分别覆盖广度、横评与机制消融，缺一不可。

三条技术路线，各自的赌注

路线 A · 记忆 bank

显式写入，条件化读取

MemoryVLA、MemoryVLA++、Chameleon 把历史写成可检索的 bank / stack。赌注是「未来的查询可以被一个学出来的相似度函数近似」，代价是写入规则与容量管理要自己设计。

路线 B · 原生历史

不压缩，靠复用扛成本

SimpleMemVLA、NativeMEM 尽量保留原始视觉，靠 KV 前缀复用或单 token 压缩把成本压下来。赌注是「提前压缩一定丢证据」，代价是上下文长度与显存。

路线 C · 折叠状态

把历史折进固定状态

VPWEM、ReMem-VLA 用递归压缩或 recurrent query 维持固定预算。赌注是「任务需要的历史信息有低维结构」，代价是不可逆的信息损失。

快速选型

任务特征优先路线代表工作
近期遮挡、细粒度视觉证据保留原生历史视频SimpleMemVLA、NativeMEM
分钟级多阶段任务且有实时约束短期视频 + 长期文本摘要MEM
少数关键事件需在很久后回忆任务条件关键帧 / memory bank 检索MemER、MemoryVLA
当前画面相同、但历史决定正确动作几何事件 + 控制条件检索Chameleon
需要固定预算的持续在线状态递归压缩或 recurrent queriesVPWEM、ReMem-VLA
核心是追踪动作带来的状态改变显式状态差分 tokenEvoMem-VLA
既要记过去又要预测后续状态memory bank + latent world modelMemoryVLA++

推荐阅读顺序

阶段阅读顺序目标
先建立直觉MemoryVLA → MemER看清「写入 bank + 检索」这条最主流路线，以及检索式记忆的最小实现。
再补成本约束SimpleMemVLA → NativeMEM理解「不压缩」与「压成一个 token」这两个极端各自的代价。
然后是分层与检索条件MEM → Chameleon → EvoMem-VLA比较双尺度、控制索引与状态差分三种记忆单位。
最后是固定预算与前瞻VPWEM → ReMem-VLA → MemoryVLA++判断该把历史折进状态，还是额外学一个未来模型。
验收MIKASA-Robo → RoboMME → RMBench用统一协议检验「少了记忆就做不对」是否真的成立。

和前两个专题怎么接

专题一给「事件」

它决定哪一刻值得写：候选、确认、提交、维护。产出的是一条带起止与证据的语义事件，而不是连续帧缓存。

专题二给「存储」

它决定事件以什么形式落地：KV、摘要、量化位宽、分层预算。产出是一份能在显存上限内被检索的历史。

本专题补上最后一环：记忆如何改变动作。工程上最容易接错的地方也在这里——事件检测的 F1 再高，只要写入粒度、索引条件与动作接口对不上，闭环表现就不会提升。反过来，凡是能在真机上报告长时程任务成功率的工作（如 MemoryVLA、MEM、MemER），都同时交代了写入规则、检索条件与动作头的接法，值得作为模板。
