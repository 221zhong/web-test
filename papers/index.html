Topic 01 · Key Event Detection

历史关键事件检测

VLA 如何从连续观测中决定「哪一刻值得写入长期记忆」，并保证写进去的历史在以后还能被找回

← 返回总站 专题二 · KV Cache 与事件记忆
结论先行：这条链条上没有一个工作可以整段照搬。可组合的最小方案是——用 KEMO 的运动学峰值做候选（纯本体信号、几十行代码），用 DDM-Net 的「模态内先聚合、跨模态再互证」结构做语义确认，用 CAG-QIL 的边沿触发提交器决定何时落库，用 Hierarchical Event Memory 的尺度树与频率预算解决长期容量，最后用 Ego4D EM 的查询命中率而不是边界 F1 验收。冲突点集中在两处：DDM-Net 与 Motion-Aware Self-Supervision 依赖中心窗口（含未来帧），与 CAG-QIL、OAT、MATR 的「不可回改」在线约束直接对立；KEMO 的峰值确认窗会推迟写入，短阶段任务可能等不到确认就进入下一步。

3. 架构综合：模块互补与不兼容点

L0 · 候选

本体信号优先

KEMO 的关节减速峰值与 FlowGEBD 的像素存活率都是零训练方案。机器人场景里前者信号更干净，可先用它把每个控制步压成「普通 / 可疑」两类，再决定是否调用视觉模型。

L1 · 确认

两阶段互证

DDM-Net 的 intra → cross 顺序可直接扩成三路：motion 先在模态内聚合，再由 appearance 与 robot state 分别核对。OadTR 的 task token 提供「现在处于哪个阶段」的上下文，Event-VStream 的三线索打分提供阈值化封装。

L2 · 提交

边沿触发写入

CAG-QIL 给出可学习的提交判据，OAT 给出窗口级实例解码，MATR 给出「按需写入 + 终点回溯」，HAT 给出长历史压缩注入。四者可拼成一个 pending / committed 双态写入器。

L3 · 维护

预算与合并

Hierarchical Event Memory 的尺度树与频率预算，回答「多尺度事件各占多少槽位」；溢出时的相似合并优先于 FIFO，可直接替换常规的滑窗淘汰。

结构性冲突（选型时必须先做取舍）：

  • 因果性冲突。DDM-Net 与 Motion-Aware SSL 都依赖中心窗口，判定一个边界时要用到它之后的帧；CAG-QIL、OAT、MATR、HAT 则要求提交后不可回改。二者同用，必须把 DDM-Net 改成单侧历史窗口，并把由此产生的一个窗口延迟计入系统指标——这正是 KEMO 用 20–60 帧确认窗换来的代价。
  • 可改写性冲突。On-TAL 系列（CAG-QIL / OAT / MATR / HAT）把「已提交不可改」当作定义的一部分，而 Hierarchical Event Memory 依靠合并与更新维护记忆。若同时要低延迟与可纠错，需要把「提交」与「落库」拆成两级：提交只冻结边界，落库仍允许按相似度合并。
  • 类别开闭冲突。OadTR 与 HAT 都是闭集动作类别，DDM-Net 与 FlowGEBD 类别无关。VLA 的子任务空间通常是开放且任务特定的，因此语义确认层应保持类别无关，把类别信息交给任务指令而不是分类头。
  • 记忆形态冲突。Hierarchical Event Memory 存 proposal 特征，KEMO 存有序 memory token，Event-VStream 存 L2 归一化的事件级嵌入。三者的检索接口不可互换；若下游是 VLA 策略而非 VLM 问答，KEMO 的 token 注入形态最省改造。

4. 推荐阅读顺序

阶段顺序目标
建立最小闭环KEMO → DDM-Net先看端到端怎么跑通，再补语义确认为什么需要两阶段证据。
理解在线提交CAG-QIL → OAT → MATR → HAT按「不可回改」这条约束读，比较四种提交粒度与延迟来源。

验收Ego4D EM用未来查询命中率检验写入质量，而不是只看边界 F1。
